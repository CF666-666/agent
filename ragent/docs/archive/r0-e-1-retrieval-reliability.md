# R0-E-1 检索预算与取消传播验收记录

状态：已完成（2026-08-13）

## 目标

修复超图实体抽取可运行约 45 秒、而客户端已在 20 秒断开后后台任务仍继续占用线程的问题。本闭环只处理检索执行可靠性，不调整实体抽取、关系路径排序或召回策略。

## 实现

- HTTP 请求进入时创建基于 `System.nanoTime()` 的单一绝对 deadline，默认 18 秒，并显式传递到子问题与检索通道。
- 超图通道使用独立的可配置 7 秒预算；实际预算为通道预算与请求剩余时间的较小值，且从任务提交时开始覆盖排队与执行。
- 超时会取消通道与子问题 Future；客户端断开或主动停止会取消整个请求未完成的检索工作。
- 实体抽取注册可取消的 LLM 调用；取消会向下传递到 OkHttp `Call.cancel()`，而非仅中断 Java Future。
- 新增 `retrieval_status` SSE 事件，带请求汇总及通道明细（`status`、`timedOut`、`cancelled`、`budgetMillis`、`elapsedMillis`）。`references` 仅发送真实证据，不伪造空引用。
- 评测脚本将正常完成的零引用作为质量样本；`TIMED_OUT`、`CANCELLED`、`FAILED` 单独统计并从 Hit@K/MRR 分母排除。

## 验收证据

- Bootstrap 定向测试：13 项通过，覆盖超时线程释放、排队预算、超图降级、执行上下文取消、SSE 事件顺序与既有检索兼容性。
- Infra-ai 定向测试：2 项通过，MockWebServer 验证同步模型 HTTP 请求在取消后立即结束。
- 真实 Docker HTTP/SSE 探针通过：事件顺序为 `retrieval_status → references → done`；超图通道完成耗时约 4.9 秒，返回状态 `COMPLETED`，引用中不含伪造的超图空占位。

## 对 R0-E 的影响

R0-E 的运行可靠性阻塞已解除，可以重新执行四类 schema v3 分批评测。新的评测报告生成、合并与归档前，不得将既有部分报告或任何 Hit@K/MRR 数字当作受控质量基线。

## 复审后的收敛项

- 请求级 deadline 现在主动到期取消，覆盖查询改写、意图解析、子问题、MCP 与各检索通道；前置阶段已过期时直接返回执行状态，不启动后续检索。
- 通道定时器在提交任务前启动，因此线程池采用 `CallerRunsPolicy` 时也不会绕过超图预算。
- 请求级 `timedOut/cancelled` 仅表示整个请求的 deadline/取消状态；通道级超时保留在 `channels[]`，不再把已完成文本或图像证据从 Hit@K/MRR 分母排除。
- 本次为解决经用户确认的 R0-E 可靠性阻塞，改动了既有 Pipeline 与检索核心。后续应把执行上下文和调度策略进一步收敛为独立扩展 seam，避免同类可靠性需求继续直接进入核心编排。
