1. **企业级 Agentic RAG 智能体平台(多模态 RAG + 超图推理)**

## 二、项目简介(100 字左右)

基于 Java 17 + Spring Boot 3 从 0 到 1 自研的企业级 Agentic RAG 智能体平台,面向工业/制造场景完成多模态升级:支持文本、设备图纸、扫描件的联合解析与检索,创新引入**超图推理引擎**解决跨文档多跳关系问答,回答以**可溯源引用**(文本卡片 / 图纸大图 / 推理路径)呈现。覆盖文档入库 ETL、意图识别、问题重写、多路检索融合、模型路由容错、SSE 流式输出、用户中心全链路。

## 四、核心亮点(面试可展开,每条都有真实代码支撑)

### 1. 多模态 RAG 升级:让系统"看得懂图纸"
- 三路解析管道:`PdfBoxParser`(电子 PDF)+ `Tess4JParser`(OCR 扫描件)+ `QwenVLImageParser`(图纸语义描述,工业引导 Prompt)。
- 图像独立向量通道:`ImageSearchChannel` 在 Milvus `industrial_images` 集合检索,回答时把原始图纸作为 IMAGE 引用一并输出。

### 2. 超图推理引擎:补足向量检索"只认相似、不懂关系"的短板
- 自研 N 元超边模型(设备 / 工况 / 参数 / 故障 / SOP + 扩展实体),LLM 从文档抽取超边。
- 倒排索引(实体值 → 超边下标)子图匹配 + 读写锁并发安全,检索通道输出"推理路径"文本引用。

### 3. 多路检索融合 + Rerank
- 意图定向 / 向量全局 / 图像语义 / 超图四通道并行,后处理链:去重 → 多源加权融合(min-max 归一化 + 权重配置)→ Rerank 重排。
- 检索结果结构化转换为 references(类型 / 标签 / URL / 片段),SSE 事件推送给前端按类型渲染。

### 4. 企业级工程能力
- 模型路由:多供应商候选 + 优先级调度 + 首包探测缓冲 + 自动降级,单模型故障无感切换。
- 分布式排队限流:Redisson 信号量 + ZSET 排队(Lua)+ Pub/Sub 唤醒,SSE 推送排队状态。
- 全链路 Trace:重写 → 意图 → 检索 → 生成,基于 AOP + TTL 跨线程透传。
- 文档入库 Pipeline:节点编排(Fetcher → Parser → Multimodal → Chunker → Indexer),配置化可扩展。

## 五、量化指标(可量化陈述,源自项目真实数据)

- 后端 Java 约 **400 个源文件 / 4 万行**,前端 React/TS 约 **1.8 万行**,数据库 **20+ 张表**。
- 生产数据规模:**FAQ 知识 210 条、设备图纸 12 张、超图超边 633 条**。
- 检索通道 **4 路并行**(意图 / 向量 / 图像 / 超图),后处理链 **3 级**(去重 / 融合 / Rerank)。
- 支持 **3 家**模型供应商(百炼 / SiliconFlow / Ollama)、**4 个**聊天候选模型、**2 个** Embedding 候选、**2 个** Rerank 候选。
- 前端页面/组件 **22+**,覆盖聊天、管理后台(仪表板 / 知识库 / 意图树 / 入库监控 / 链路追踪 / 用户管理)。
- 一键容器化:**Docker Compose 编排 9 个服务**(PG / Redis / RocketMQ / Milvus 全家桶 / 后端 / 前端),冷开机 5-15 分钟拉起。

## 六、面试追问应答要点(高频问题速记)

| 面试官问 | 你的回答要点 |
|---------|------------|
| 为什么用 Milvus 不用 ES？ | 高维稠密向量 ANN 检索、10 亿级扩展、与 pgvector 双写做效果对比 |
| 超图和普通图有什么区别？ | N 元关系(一条超边连接 2+ 实体),表达"油泵→密封圈→扭矩"这类复合事实,倒排索引子图匹配 |
| 多模态图片怎么检索？ | Qwen-VL 生成工业语义描述 → 描述文本向量化入库 → query 语义检索命中 → 返回原始图纸 URL |
| 模型挂了怎么办？ | 候选路由 + 优先级 + 健康探测 + 熔断降级,SSE 首包缓冲保证切换无脏数据 |
| 大量并发怎么限流？ | Redis ZSET 排队 + 信号量 + Lua 原子判定 + Pub/Sub 唤醒,防惊群、许可过期防死锁 |
| 如何保证回答可溯源？ | 检索结果结构化 references,SSE 先发引用再发正文,前端分类型渲染 |
